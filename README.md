# Apex Rush — Web Version (Next.js + Three.js)

The same arcade racer as the Unity build, running entirely in the browser.
**Zero assets required** — track geometry, car models, particles, and even the
engine sound are all generated by code.

## Run it

```bash
cd web
npm install
npm run dev
```

Open http://localhost:3000. Production build: `npm run build && npm start`.

## Controls

| Action | Keyboard | Gamepad (standard mapping) |
|---|---|---|
| Steer | A/D or ◄/► | Left stick |
| Throttle / Brake-Reverse | W / S or ▲/▼ | RT / LT |
| Handbrake (drift) | Space | B |
| Nitro | Shift | A |

## Features

- 2 generated tracks (Harbor Loop, Canyon Circuit), 3 cars with distinct stats
- Circuit mode (1–7 AI with Easy/Normal/Hard + gentle rubber-banding) and Time Trial
- Arcade physics: grip assist, handbrake drifts that charge nitro, speed-sensitive
  steering, wall glance-off instead of dead stops
- Chase camera with speed FOV + nitro kick + shake; drift smoke and nitro flame particles
- Synthesized engine audio (pitch follows a 5-speed virtual gearbox), skid + nitro noise
- HUD: speedo, gear, nitro gauge, lap/position, lap timers, live minimap
- Menus: main, car select, race setup, settings (persisted to localStorage)

## Architecture

```
app/            Next.js shell (App Router; the game is fully client-side)
components/
  Game.jsx      Screen state machine + all menus (React)
  RaceView.jsx  Mounts the engine, renders HUD; per-frame data goes into DOM
                refs so racing causes zero React re-renders
game/
  engine.js     Composition root: scene, spawn grid, rAF loop, callbacks to React
  vehicle.js    Arcade car physics + CAR_MODELS roster
  track.js      Spline → road/walls/scenery meshes + projection queries + TRACKS
  ai.js         Spline-following driver, difficulty tiers, rubber-banding
  race.js       Countdown, continuous lap progress, timing, positions, finish
  camera.js     Chase cam: yaw lag, speed FOV, shake
  audio.js      WebAudio-synthesized engine/skid/nitro
  fx.js         Sprite-pool particles (smoke, nitro flames)
  input.js      Keyboard + gamepad polling
  utils.js      Math helpers
```

The contract mirrors the Unity build: `Vehicle.update(dt, input)` takes the same
input object from a human (`input.js`) or a bot (`ai.js`), so AI obeys identical
physics. React never touches Three.js internals; the game reports through
`onHud` / `onCountdown` / `onResults` callbacks only.

## Handling tuning — where the knobs live

| Feel | File / knob |
|---|---|
| Acceleration, top speed, per-car character | `vehicle.js` → `CAR_MODELS` stats |
| "Carves vs. slides" | `vehicle.js` → `gripRate` (7.5 normal, 2.0 drifting) |
| Drift entry/exit | `vehicle.js` → slip thresholds (14° in, 5° out), yaw ×1.65 |
| Steering twitchiness at speed | `vehicle.js` → `lerp(1, 0.42, normalizedSpeed)` |
| Sensation of speed | `camera.js` → FOV boosts; cheaper than physics changes |
| AI aggression | `ai.js` → difficulty tiers, `rubberBandStrength` |
| New track | `track.js` → add control points to `TRACKS`; everything else is generated |
